C. Order lifecycle

C1 Proposal: Research → Risk gates → Proposal → APPROVE | REJECT | DO NOT TRADE

C2 Entry (3b/3c): E*TRADE: Preview → Place → poll fill → place STOP + LIMIT separately (no API bracket create). IBKR: bracket array in one POST.

C3 While open: Poll orders/positions. Partial fill → resize exits. Kill switch → no new entries; 3c cancels all working orders.

C4 Exit: Stop or target fills → cancel sibling. Manual sell → journal MANUAL OVERRIDE.

C5 Emergency: DO NOT TRADE → Kill ON → Cancel all → verify → reconcile before resume.

C6 Post-trade: Transaction in API → journal SYNCED. Update cash from balance API (read only).

Step A — Sandbox (≈15 min · do anytime, even now)

  • Log in to E*TRADE account (funding not required for sandbox)
  • Open us.etrade.com/etx/ris/apikey → generate Sandbox consumer key + secret
  • Store key/secret in password manager (not email, not repo)
  • Download sample app from developer.etrade.com/home (Python recommended)
  • Run OAuth against sandbox → confirm access token
  • Call sandbox List Accounts → confirm JSON parses

Step B — Live / production key (~4–8 weeks before Phase 3a)

  • Complete API User Intent Survey (personal automation, own account)
  • Sign API Developer Agreement on Getting Started page
  • Receive Individual Live consumer key + secret (immediate on page)
  • Sign Market Data Agreement (required for quote API)
  • Calendar: annual Market Data Attestation required thereafter

  • OAuth: manual verification code OR request callback URL via secure message (Technical Issues → E*TRADE API)
  • Document token rules: renew if >2h idle; full re-login after midnight ET
  • Point sync at dedicated strategy account only
  • First production calls read-only: List Accounts → Balance → Positions → Transactions

  • Secure storage: consumer key, consumer secret, token secret

4. Quick Reference

Daily paper routine (September)

  1. EOD: Review picks; log NO TRADE or would-have entries (limits, stops, targets).
  2. Pre-market: Refresh watchlist; note gaps vs Plan.
  3. Pre-purchase: Deploy size, risk gate, GO/NO-GO before any would-be buy.
  4. Weekly: Compare paper results to Plan tab (hit rate, hold time, gross).

Manual trade pattern (Q4) — bracket equivalent

  1. Limit buy at planned entry.
  2. On fill: place GTC stop + GTC limit target for filled quantity.
  3. Partial fill → stop/target for filled shares only.
  4. One exit fills → cancel the other (OCO).

E*TRADE website supports brackets manually. API v0 requires separate stop + limit orders after fill.

DirectionPossible?How
